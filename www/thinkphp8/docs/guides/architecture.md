# 项目架构文档

本文档详细描述了电子商务应用的架构设计。

## 系统架构

项目基于ThinkPHP 8框架开发，采用MVC架构模式，使用PostgreSQL作为数据库存储。整体架构如下：

```
+-------------------+
|      客户端        |
|  (Web/App/小程序)  |
+--------+----------+
         |
         | HTTP/HTTPS
         v
+--------+----------+    +----------------+
|     应用层         |    |    缓存层      |
|  ThinkPHP 8框架   +--->|    Redis      |
+--------+----------+    +----------------+
         |
         | SQL
         v
+--------+----------+
|     数据库         |
|   PostgreSQL      |
+-------------------+
```

## 代码架构

项目代码遵循ThinkPHP 8的目录结构，主要模块划分如下：

### 控制器层 (app/controller/pg)

控制器负责接收请求、参数验证、调用服务层处理业务逻辑，并返回响应结果。

- `UserController.php` - 用户相关接口
- `GoodsController.php` - 商品相关接口
- `CartController.php` - 购物车相关接口
- `OrderController.php` - 订单相关接口

### 模型层 (app/model/pg)

模型层负责数据库交互，定义数据表结构、关联关系和数据操作方法。

- `User.php` - 用户模型
- `UserAddress.php` - 用户地址模型
- `Goods.php` - 商品模型
- `GoodsSku.php` - 商品规格模型
- `Category.php` - 分类模型
- `Brand.php` - 品牌模型
- `Cart.php` - 购物车模型
- `Order.php` - 订单模型
- `OrderItem.php` - 订单商品模型
- `OrderLog.php` - 订单日志模型

### 服务层 (app/service/pg)

服务层负责处理业务逻辑，封装复杂业务处理，提供事务管理等功能。

- `UserService.php` - 用户服务
- `GoodsService.php` - 商品服务
- `CartService.php` - 购物车服务
- `OrderService.php` - 订单服务

### 验证器 (app/validate/pg)

验证器负责请求参数验证，确保数据符合业务规则。

- `UserValidate.php` - 用户数据验证
- `AddressValidate.php` - 地址数据验证
- `GoodsValidate.php` - 商品数据验证
- `CartValidate.php` - 购物车数据验证
- `OrderValidate.php` - 订单数据验证

### 异常处理 (app/exception)

异常处理类负责捕获和处理业务异常，提供统一的异常处理机制。

- `BusinessException.php` - 业务异常类
- `ExceptionHandle.php` - 全局异常处理器

## 数据流

系统的数据流向遵循以下流程：

1. 客户端发送HTTP请求到控制器
2. 控制器使用验证器验证请求参数
3. 控制器调用服务层处理业务逻辑
4. 服务层调用模型层进行数据操作
5. 模型层与数据库交互
6. 服务层处理业务结果，可能包含事务管理
7. 控制器接收服务层返回的结果，进行响应包装
8. 响应结果返回给客户端

示例流程图（用户注册流程）：

```
客户端 -> UserController.register() -> UserValidate.check() -> UserService.register() -> User.create() -> 数据库
   ^                                                                |
   |                                                                v
   +----------------------------------------------------------------+
                          返回注册结果
```

## 扩展性设计

项目架构设计考虑了系统的扩展性，主要体现在以下几个方面：

1. **服务层封装**：业务逻辑封装在服务层，控制器只负责请求处理和响应，便于业务逻辑复用和扩展

2. **模型关联**：使用ThinkPHP的模型关联功能，便于扩展数据关系

3. **事务管理**：使用服务层统一管理事务，确保数据一致性，便于扩展复杂业务场景

4. **异常处理**：统一的异常处理机制，便于添加新的业务异常类型

5. **验证器**：独立的验证器类，便于扩展验证规则

## 安全设计

项目在安全方面做了以下考虑：

1. **参数验证**：所有请求参数都经过验证器验证，防止非法参数

2. **密码加密**：用户密码使用哈希算法加密存储

3. **Token认证**：使用JWT实现用户认证，确保API安全

4. **事务保障**：重要业务操作使用事务确保数据一致性

5. **异常处理**：统一处理异常，避免敏感信息泄露
